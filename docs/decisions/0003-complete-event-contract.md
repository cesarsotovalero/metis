# ADR 0003: complete the offline event contract without activating later subsystems

Accepted 2026-11-05. Implement M0 F02's remaining event families and the persistence needed to reconcile their lifecycle metadata. Keep the four-crate offline architecture from ADR 0001. This supersedes ADR 0002's blanket cross-epoch ambiguity only when an explicit, unbranched resume chain resolves the order.

Retain schema version 1: existing event shapes are unchanged on the wire, and the accepted kind set is expanded additively. Old binaries reject unsupported kinds safely. The JSON Schema remains strict, including empty lifecycle payloads and nested measurement objects. jsonschema 0.60.2 executes the embedded contract at the application boundary with default HTTP/file resolver features disabled. Additional semantic checks enforce matching task IDs, non-self resume links, and evidence references for verified capability assertions. Unknown extension objects are rejected rather than retaining unfiltered content.

Later-family payloads are typed metadata references and counters, not executable commands or optimization authorization. Synthetic full-local/capability/policy/delivery assertions cannot change capture permissions or enable artifact retrieval. Future adapters must validate their upstream contracts and permissions independently. Artifact bodies, projection contracts, graph materialization, policy evaluation and retrieval grants remain in their own milestones.

Reconcile lifecycle from immutable events. Explicit epoch links determine resume order; producer sequence determines within-epoch order. Unresolved or branched lineage remains unknown. No wall-clock-derived durations are claimed. Task outcomes retain assertion provenance and oracle version; missing/conflicting outcomes remain unavailable. Cancellation is distinct from failure, and conflicting call terminals are unknown rather than selected by arrival order. Calls shared across producers/epochs remain rejected until authoritative reconciliation exists.

Migration 3 adds event metadata, task records, task-linked call tables and epoch records. Source event JSON is never rewritten; auxiliary metadata is backfilled separately. Changes to call tables add status/foreign-key constraints and preserve data inside a single migration transaction. The driver validates exact stored migration text, applies all pending schema changes and backfills in one transaction, and refuses newer schemas before write pragmas. Errors roll back schema version, migration records and views together. No artifacts or other future subsystem tables are generated without a consumer.

Fixtures and conformance tests cover all payloads, schema/runtime rejection, atomic imports, source preservation, old schema upgrades/restarts, failed-backfill rollback, epoch ambiguity, task provenance and call conflicts. This completes the scoped event-contract task; repository/worktree identity persistence, a concurrent writer actor and broader release conformance remain M0/daemon foundation work.
