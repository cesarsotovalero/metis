# Initial threat model

Trust user-selected storage configuration; treat input fixture JSON as untrusted. Strict typed fields reject bodies/extensions, enforce schema version, bound files/lines, and use SQL parameters. Never execute fixture contents. Errors avoid echoing fixture bodies. Identities are metadata: operators must not put secrets in them.

SQLite and sidecars live under an owner-only directory on Unix. This is not encryption. A compromised same-user process, malicious symlink in a user-chosen data path, or direct database edits are outside this initial local slice. Do not use a shared or attacker-controlled home directory. Runtime accepts authenticated local Unix-socket clients on Linux and offers no retrieval or TCP/HTTP listener. Broader path hardening, retention, live capture policy and destructive migration controls remain future work.

The schema validator compiles a checked-in schema using local references only, with HTTP and file resolvers disabled. Nested measurements and empty lifecycle variants reject unknown fields. Malformed imports do not echo bodies or commit a prefix. Metadata about verified capabilities, full-local capture, or policy activation remains untrusted synthetic evidence and cannot change observer permissions, capture settings, or execution mode. Exact bytes, recovery grants and live delivery are not implemented by storing those observations.

M1 O01 adds Linux kernel peer-UID checks, a private random owner token, strict session/producer/epoch binding and capability grants. This does not isolate mutually hostile processes sharing the same owner: an owner who can read the token can explicitly bind a new session connection. Runtime/spool files are owner-only; symlink endpoints and unsafe stale files are rejected, and singleton lock ownership precedes cleanup. Existing arbitrary ancestor-path replacement and compromised same-owner processes are outside the initial local threat boundary.

Frames, batches, connections and writer queues are bounded. Slow sends use absolute frame deadlines. Failure notices contain only static reason codes and aggregate health counters, with bounded nonblocking admission and a rotating 64 KiB spool. Disk failures and notice overflow are observable rather than silently treated as success. Expired queued writes do not start; an already executing transaction can finish after a client timeout, so responses never authorize automatic replay. No extra user/agent permissions or live capture capabilities are granted.
